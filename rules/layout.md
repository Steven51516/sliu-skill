# Project layout

Projects live under the projects root named by the project's scope file (`~/projects/<name>/` on Engaging). Work is organised by **map** (one destination, e.g. "baselines", "transfer", "pathway priors") and **ticket** (one sharp question on that map; its runs are assets inside it, not tickets). Where maps and tickets live is the project's issue tracker (`docs/agents/issue-tracker.md`); with the local tracker it is the `maps/` folder below. Create directories when first needed.

```
AGENTS.md       read by every agent: read-first pointers (scope, style, team, issue tracker), code location, project notes
CLAUDE.md       @AGENTS.md + the Claude-only imports and session rules
docs/agents/    team.md: planner, worker, reviewer (agent, model, effort), how to call each
                issue-tracker.md: where maps and tickets live and how to claim, block, query and resolve them
docs/decisions.md   cross-map decisions, one line each, newest first. Map decisions live in each map's Decisions so far
GLOSSARY.md     project terms (created when the first one settles)
OVERVIEW.md     the project's overview, ≤25 lines: destination, one line per phase or map (linked), now, reference points
STATUS.md       GENERATED by `research-status` from OVERVIEW.md + maps/ (local tracker). Never edited by hand
maps/           (local tracker)
  T1-<slug>/
    map.md                    destination, notes, decisions so far (index), not yet specified (fog), out of scope
    tickets/NN-<slug>/        one folder per ticket: ticket.md + its code + small results
    archive/                  consolidated closed tickets (never deleted)
common/         code or envs used by more than one ticket (e.g. common/env/ build scripts)
resources/      the human's inputs: BRIEF.md, LINKS.md, papers/, prior-work/, other/; INTAKE.md logs what was read; repos/ (gitignored)
logs/           job logs (gitignored)
artifacts/  ->  <pool root>/<name>      checkpoints, datasets (gitignored; a link to the scope file's pool root, else a folder)
scratch/    ->  <scratch root>/<name>   regenerable intermediates, per ticket: scratch/<ticket id>/ (gitignored; link or folder)
```

Rules of thumb
- Messy is fine inside a ticket folder. `map.md` and `OVERVIEW.md` stay clean and short: they are indexes, not stores.
- Large outputs never go in a ticket folder: `scratch/<ticket id>/` or `artifacts/<ticket id>/`, and the ticket says where.
- Research notes from `research` tickets go where the project already keeps such notes, else in the ticket's folder.
