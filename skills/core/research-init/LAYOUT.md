# Project layout

Projects live under the projects root named by the project's scope file. Work is organised by **map** (one destination, e.g. "baselines", "transfer", "pathway priors") and **ticket** (one sharp question on that map; its runs are assets inside it, not tickets). Where maps and tickets live is the project's issue tracker (`docs/agents/issue-tracker.md`); with the local tracker it is the `maps/` folder below. Create directories when first needed.

```
AGENTS.md       read by every agent: read-first pointers (scope, style, delegation, issue tracker, domain docs), code location, project notes
CLAUDE.md       @AGENTS.md + the Claude-only imports and session rules
docs/agents/    delegation.md: where delegated work and reviews go (by topic, kind or role), how each agent is called
                issue-tracker.md: where maps and tickets live and how to claim, block, query and resolve them
                domain.md: how skills read GLOSSARY.md and docs/decisions.md
docs/decisions.md   cross-map decisions, one line each, newest first; a longer one links an ADR in docs/adr/. Map decisions
                live in each map's Decisions so far
GLOSSARY.md     project terms (created when the first one settles)
STATUS.md       GENERATED by `research-status` from maps/ (local tracker): milestones (closed maps' outcomes) and open
                maps. Never edited by hand; what is live: `research-status --now`
maps/           (local tracker)
  M1-<slug>/
    map.md                    destination, notes, decisions so far (index), not yet specified (fog), out of scope
    tickets/NN-<slug>/        one folder per ticket: ticket.md + its code + small results
    archive/                  consolidated closed tickets (never deleted)
common/         code or envs used by more than one ticket (e.g. common/env/ build scripts)
resources/      the human's inputs: BRIEF.md, LINKS.md, papers/, prior-work/, other/; INTAKE.md logs what was read; repos/ (gitignored)
logs/           job logs (gitignored)
artifacts/  ->  <pool root>/<name>      checkpoints, datasets (gitignored; a link to the scope file's pool root, else a folder)
scratch/    ->  <scratch root>/<name>   regenerable intermediates, per ticket: scratch/<ticket id>/ (gitignored; link or folder)
```

Rules of thumb
- Messy is fine inside a ticket folder. `map.md` stays clean and short: it is an index, not a store.
- Large outputs never go in a ticket folder: `scratch/<ticket id>/` or `artifacts/<ticket id>/`, and the ticket says where.
- Research notes from `research` tickets go where the project already keeps such notes, else in the ticket's folder.
